01 / Tests existed. A programme did not.

Tests existed. A programme did not.

Mable already ran A/B tests with an external agency. But results were scattered across decks, write-ups were inconsistent and ideas lacked a shared route into a prioritised test. Clicks and signup starts sometimes looked positive while completed signups moved in the opposite direction.

The objective was not to claim ownership of every experiment. It was to make testing repeatable, interpretable and increasingly operable by the internal web squad.

02 / Build the operating system

Build the operating system

We introduced a four-stage workflow: Idea → Candidate → Approved and running → Completed. Every candidate needed a defined problem, testable hypothesis, business metric, behavioural metric and review path.

Supporting infrastructure included Confluence briefs and hubs for Mable and HomeMade, a Figma testing roadmap, GA4 and Looker reporting, practical playbooks, regular design/CRO catch-ups and a searchable record of past experiments. The platform transitioned from Optimizely on WordPress toward VWO and Contentful.

03 / A measurable testing pipeline

A measurable testing pipeline

The agency programme progressed from a broad idea backlog into a substantial series of launched and completed experiments. A meaningful subset achieved statistically supported wins. These were programme-wide results, not experiments personally built or run end to end.

The agency’s year-end summary reported positive year-on-year signup conversion performance during the programme period. This is descriptive context, not a causal estimate of experimentation alone.

The original programme reports contain internal performance figures and test-level detail. This public summary deliberately omits those figures and distinguishes shared programme outcomes from my contribution.
04 / What actually moved the funnel

What actually moved the funnel

Several experiments demonstrated that clearer paths and better evidence can outperform cosmetic redesigns:

Mobile hero

Larger mobile actions and visible proof points improved reported signup and first-job outcomes.

Menu clarity

More explicit support-worker search language improved the path into signup.

Funding navigation

An in-house navigation test indicated client-side gains alongside worker-side trade-offs; evidence was directional.

Audience-specific pricing

Separating client and worker pricing improved worker signup starts, while client outcomes were broadly level.

05 / The losing tests were useful too

The losing tests were useful too

A funding quiz before signup looked helpful but added effort before value; most exposed users never started it, and downstream conversions deteriorated. A shortcut increased signup starts while completed signups fell. A role selector added mobile taps and reduced signups.

The resulting measurement principle was simple: judge experiments by completed signups and first jobs, not clicks alone. Guardrails also need to account for both sides of the marketplace: a client-side win can coincide with fewer worker signups.

06 / From agency-led to in-house

From agency-led to in-house

A small set of experiments was designed, built and analysed in-house during the transition period.

The programme now has a dedicated CRO owner responsible for its roadmap. The contribution described here centres on process design, briefs, experiment design/build/QA, documentation and enabling the squad—not claiming sole authorship of the programme-wide gains.

Next: ship confirmed wins with release QA, extend high-intent supply messaging, and move from isolated page tests toward whole-journey optimisation.
